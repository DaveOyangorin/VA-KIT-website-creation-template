SECTION 8 — WEBSITE CONTENT SYSTEM
================================================================================

This section governs how Fravata writes website pages — not blog posts.
The voice and humanization rules from FRAVATA_IDENTITY.txt apply to ALL
website copy. The SEO rules from FRAVATA_SEO_KNOWLEDGE.txt apply in full.

What's different from blog mode:
  - Word count per section is shorter (focused, conversion-aware)
  - Every H1 must contain the primary keyword + location (for local businesses)
  - CTAs appear at the end of EVERY section, not just at the end of the page
  - Schema is page-type specific (not BlogPosting — see templates below)
  - Copy must serve TWO masters: Google crawler + human visitor scanning fast

--------------------------------------------------------------------------------
8.1 WEBSITE COPY WRITING PROCESS
--------------------------------------------------------------------------------

When /page or /sitecopy is triggered:

STEP 1 — UNDERSTAND THE BUSINESS
  Pull from: MAMMATA audit report (if available) or the project brief
  Establish:
    → Primary service(s) — what does the business DO?
    → Primary location(s) — what city/region do they serve?
    → Target customer — who is the ideal client?
    → Key differentiators — what makes this business worth calling?
    → Competitors — who ranks on page 1 for their target keywords?

STEP 2 — KEYWORD MAPPING
  Every page gets exactly ONE primary keyword. Map before writing.
  Homepage   : "[service] [city]" or "[brand] [category]"
  Service pg : "[specific service] [city]" (e.g., "local seo services salt lake city")
  Location pg: "[service] [neighborhood/city]" (e.g., "chiropractor draper ut")
  About pg   : "[business name]" + "[founder name] [profession]"
  Contact pg : "contact [business name]" + "[service] consultation [city]"

  Check volume in the keyword file Angelo put in INBOX before finalizing.

STEP 3 — WRITE CONTENT (follow page templates in 8.2)
  Every page must have:
    → A unique H1 (not shared with any other page on the site)
    → Meta title ≤60 chars (primary keyword first)
    → Meta description 150–160 chars (keyword + CTA + differentiator)
    → At least 300 words of body content (target 600–800 for service pages)
    → Minimum 1 internal link to another page
    → Schema block (see 8.3 for page-type schemas)

STEP 4 — QUALITY CHECK
  Run website copy quality check (Section 8.4) before delivering.

STEP 5 — SAVE OUTPUT
  Save to: OUTBOX\ (see the kit's file names)

--------------------------------------------------------------------------------
8.4 WEBSITE COPY QUALITY CHECKLIST
--------------------------------------------------------------------------------

Run this checklist on every page before delivering copy to the client.

PAGE STRUCTURE:
  [ ] H1 is unique — not used on any other page on the site
  [ ] H1 contains the primary keyword AND a differentiator
  [ ] H1 contains location name (for local pages)
  [ ] H2s form a logical hierarchy — each is a distinct sub-topic
  [ ] No heading levels are skipped (H1 → H2 → H3, never H1 → H3)
  [ ] Every section has at minimum 2 paragraphs of body copy

SEO:
  [ ] Meta title ≤60 chars, primary keyword first
  [ ] Meta description 150–160 chars with keyword + CTA
  [ ] Primary keyword appears in H1, first paragraph, at least one H2
  [ ] At least 1 internal link (to another page on the same site)
  [ ] All external links have rel="noopener" and target="_blank"
  [ ] Schema block complete and valid for this page type (see 8.3)
  [ ] Page word count ≥300 (avoid thin content flag)
  [ ] NAP consistent with GBP if this is a local page

COPY QUALITY:
  [ ] No forbidden phrases from FRAVATA_IDENTITY.txt banned list
  [ ] No contractions missing — every paragraph uses them
  [ ] H1 and first paragraph don't start with a banned opener
  [ ] CTAs are specific (not "Contact Us" or "Learn More")
  [ ] At least ONE specific, verifiable claim (stat, date, number)
  [ ] Copy does not make unverifiable promises ("guaranteed results")
  [ ] Differentiators are SPECIFIC — not generic ("experienced", "passionate")
  [ ] FAQ section uses natural language questions (as a real client would ask)
  [ ] About page includes specific dates, places, and turning points

HUMANIZATION (shorter rules apply to web copy vs. blog):
  [ ] Sentence variety: not all the same length in any paragraph
  [ ] At least one contraction per visible section
  [ ] No corporate jargon: "solutions", "synergies", "holistic approach"
  [ ] Copy can be read aloud without sounding robotic
  [ ] Emotional register: the copy sounds like a real person, not a template

CONVERSION:

  [ ] Secondary CTA appears at the bottom of the page
  [ ] CTA tells the user exactly what happens next ("we'll send the audit

  [ ] Trust signal present (review count, years in business, specific result)
  [ ] There is no reason to leave the page without either calling or
